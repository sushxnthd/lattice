# K-SYNTH-1 Run322 prospectively frozen protocol

Status: preregistration; write and commit this file to canonical GitHub branch before executing primary experiment. Never change this file after outcome inspection.

Question: can a fail-closed whole-module AST-congruence guard validate **two actions in one Python source file**, including statement-list mutations, while rejecting patches whose resulting AST differs from the intended simultaneous AST edits?

Primary synthetic design: 512 cases; eight deterministic families of 64 cases each; generator seed 3222026; one or two authorized `.py` source files per case. Families: `safe_expr_pair`, `safe_stmt_pair`, `safe_mixed`, `safe_insert_delete`, `safe_unicode_crlf`, `unsafe_comment`, `unsafe_precedence`, `unsafe_nested`. All cases contain two actions in one file, except optional untouched control file. Three unsafe families must be rejected, including either compiler rejection or guard rejection. Five safe families must produce the exact independent intended AST; no retroactive family changes. Report original compiler acceptance separately from guard acceptance and any discrepancies. Explicitly report false rejects, false accepts, and source/authority mutations.

Compiler: Run320 `compile_structural`, Run315 `node_digest`; guard shall use exact source and node SHA-256 preconditions and action authority, construct expected AST on original snapshot, validate nonoverlap, and compare whole-module `ast.dump(...,include_attributes=False)` for all affected paths. Reject overlapping and ancestor/descendant targets. A source-parse, AST or compiler error counts as rejection, not a successful patch. Never execute model code. Functional replays may execute only trusted locally generated fixtures in a separate subprocess.

Primary measures: (1) accepted safe / 320; (2) rejected unsafe / 192; (3) accepted-patch independent AST mismatches; (4) independent functional disagreements; (5) full SHA-256 source and trace manifest. The experiment is engineering validation on correlated synthetic cases, not independent repository repairs or model comparison. A priori engineering target: >= 95% safe acceptance, 100% unsafe rejection, 0 independent accepted-AST mismatches. Failure to meet these targets is a negative result, not grounds to alter the protocol.

Independent auditor must reparse raw original and patched files, independently rebuild intended AST using source-located actions and Python AST list editing, compare dumps, and rerun trusted accepted fixtures. Auditor must not import guard implementation. Preserve exact rejected error strings, SHA of original sources, action data, patched snapshots (if any), and environment details.

Scope exclusions: AST congruence is not runtime equivalence, comment preservation, security against malicious filesystem races, cross-module effect analysis, or production repair expressibility. No reference-derived localization, no claims of IR superiority, no inference if no actual model is run. Six prior qualified real repairs remain six. All 89 reserved boundary issues remain sealed. One canonical branch `research/exp003-context-order`, one open/draft/unmerged PR #9, no new PRs.
