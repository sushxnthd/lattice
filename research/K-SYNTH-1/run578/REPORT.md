# Run578: ABA counterexample to content-hash CAS recovery

A content-hash compare-and-swap recovery rule cannot certify the absence of intervening external writes. For each of 1024 seeded distinct states, a writer changed the file from A to B and then back to A. Content equality accepted the apparent unchanged file in 1024/1024 cases, despite two intervening writes. An idealized monotonic version counter rejected 1024/1024, conditional on the counter being atomically maintained by every writer. The experiment is an abstract deterministic state-machine counterexample, not an OS-level concurrency or crash-durability test. Content hashes are collision-resistant for these examples but the issue is ABA, not hash collision. A version counter cannot be assumed for ordinary repository files; without exclusive write authority or an atomic generation mechanism, the recovery verifier must report UNKNOWN regarding external-writer noninterference. This refines Run577's conservative CAS claim. No model inference, production-repair qualification, or semantic-IR superiority evidence.
