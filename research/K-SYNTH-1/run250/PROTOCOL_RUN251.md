# Run251 protocol — independent tasks and real semantic mechanism

1. Prospectively qualify independent real multi-file issues: pin commit, issue statement, editable/read-only scopes, baseline-negative checks, reference-positive checks, and withheld adversarial checks. Reject issues without executable controls. Do not open the 89 reserved boundary issues.
2. Build a genuine semantic/dataflow IR with validated symbol binding and at least one verified control/dataflow relation; expose explicit unknowns rather than hallucinated edges. Compare against information-equivalent ordinary Python with identical native-edit syntax, compiler, oracle, task information, authority and inference settings.
3. Compute repository-cluster-aware paired power for two-sided alpha=0.05 and >=80% power before collecting outcomes. Earlier 258-pair direction is insufficient for some plausible effects; the illustrative smaller-effect scenario required ~960 issue pairs across 240 repositories.
4. Preserve exact prompts/hashes, model quantization and SHA, seed, tokenizer counts, raw outputs, parser outcomes, compiler traces, functional checks, diffs, errors and cluster identifiers.
5. If IR wins, ablate dependency localization/search entropy, invalid intermediate states, semantic churn or repair loops while holding information constant. Freeze and test one unseen boundary prediction. If Python ties or wins twice under careful reformulations, pivot to a rigorous negative result.

Do not count Run250's post-hoc header-tolerant parsing as a primary result. Do not pool the single known CrossGL pilot with prospective independent task outcomes.
