# Run529: lexical-scope counterexample to Run528 atomic compiler

Ten deterministic synthetic Python cases were parsed and classified without executing untrusted code. Six assertions passed. Run528's `ast.NodeTransformer.visit_Assign` searches nested functions/classes as well as the module; a unique `x=1` inside `def f()` therefore passes its uniqueness test even though it is not a module-level assignment. A module assignment plus a local assignment is rejected as nonunique despite having one module-level site. The new bounded analyzer records lexical scope and explicitly flags dynamic namespace operations. It still accepts `if flag: x=1`, proving its conservative module-level gate is **not** a semantic soundness certificate. Source digests, full sites and raw results are in the local SHA-verified archive. No production issue or model inference was performed. This is an adversarial negative result on compiler action specification, not evidence that either representation wins.

The 89 reserved issues remain sealed; the only independently qualified real repairs remain Flask PR6096 and urllib3 PR5071. No post-hoc promotion of Werkzeug cases.
