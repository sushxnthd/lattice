# Run244 preregistration — Multi-repository functional qualification first

**Frozen 2026-10-25, before further model inference.** The Run242 five-arm results are discovery data, not powered evidence. Continue on `research/exp003-context-order` and retain draft PR #9.

1. **Task sampling.** Use the existing Run199 discovery cohort, exclude the 89 reserved boundary issues and previously used pilots. Freeze repository, issue, base commit, task statement, editable declarations, read-only facts, source hashes, and independent functional tests before any inference.
2. **Positive and negative controls.** For each task require original failure, passing independent reference repair, and seeded negative controls that fail at least one issue-specific test. Establish which changed files are causally necessary by individually reverting them; do not assume that multi-file edits are intrinsically necessary.
3. **Representation construct.** JSON-wrapped Python source is not semantic IR. A proposed semantic representation must expose typed AST/symbol/dependency facts, retain exact source bytes, and pass a reversible encoding check. Ordinary Python receives the same facts (e.g., structured comments), not less information. Freeze the transformations and verify source-fact equivalence independently.
4. **Matched action contract.** Primary comparison uses the same canonical edit protocol, compiler, declaration/decorator-preservation gate, authority set, verifier, decoding constraints, model, seed, and completion budget. A native-diff/patch baseline may be tested separately but cannot be called a pure representation ablation.
5. **Model adequacy.** Include a genuinely strong open/no-cost coding model with recorded weights hash, inference engine hash, prompts, seeds, and token counts. The prior 7B model is a feasibility baseline; its failures alone do not settle representation science.
6. **Power and clustering.** Recalculate two-sided exact McNemar power from prospective discordance and conditional-win assumptions, adjusting for repository clustering and repeated seeds. Earlier independent-pair calculations suggest ~306 pairs at conditional win .65 and ~681 at .60 (discordance .30), before clustering. 258 is not automatically adequate. No optional stopping or selective exclusion.
7. **Evidence and safety.** Preserve all raw model completions, response JSON, exact prompts, patches, compiler/evaluator traces, failures, positive/negative controls, SHA-256 manifests, and independent evaluator implementation. Run untrusted code in disposable, network-isolated, resource-limited sandboxes, not merely a credential-scrubbed subprocess.
8. **Mechanism and prediction.** Preregister authority leakage, declaration erasure, semantic churn, dependency localization, verifier-repair count and actual functional correctness. Ablate the proposed mechanism with identical information. Freeze a prediction on the 89 unseen boundary issues only after observing a genuine effect. If Python matches or wins in two controlled reformulations, pivot the thesis toward compiler/transactional safety or a rigorous negative result.

**This document is a protocol, not a claim that qualification or inference has already completed.**
